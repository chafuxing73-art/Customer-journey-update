# 用户登录 + 管理员模式 + 客户绑定权限隔离

## Context（为什么做这个改造）

当前 `sync_service` 是一个无鉴权的 FastAPI 服务：`customers.yaml` 全局共享，任何调用方都能同步任意客户、增删客户配置。用户需要把它变成多用户系统——管理员开通账号、分配客户，普通用户只能同步自己拥有或被分配的客户。同时补充同步历史、审计日志、用户启停改密、并发锁、webhook 测试等运营必需能力。

已确认的关键决策：
- 客户-用户关系：**多对多共享**（owner 创建 + admin 分配给他人）
- 存储：**customers.yaml 迁移到 SQLite**，运行时全走 DB，yaml 仅作首次种子
- 补充功能：同步历史 + 审计日志 + 用户启停改密 + 并发锁 + webhook 测试（全要）

## 数据模型

新增 `data/app.db`（权限域），与现有 `data/record_map.db`（同步映射域）分离，避免锁竞争。schema 初始化集中在 [db.py](file:///f:/项目/客户轨迹自动更新/sync_service/app/services/db.py) 的 `init_db()`。

```sql
users(id, username UNIQUE, password_hash, role DEFAULT 'user', enabled DEFAULT 1,
      created_at, last_login_at, pwd_changed_at, reset_token, reset_expires_at)
customers(code PK, name, webhook_url, sync_mode, schedule, enabled,
          owner_user_id →users, created_at, updated_at)
user_customer_assignments(id, user_id →users, customer_code →customers,
                          assigned_by →users, assigned_at, UNIQUE(user_id, customer_code))
sync_history(id, customer_code, triggered_by, trigger_source,
             total/new/updated/skipped/failed, errors(JSON), started_at, finished_at, success)
audit_log(id, actor, actor_role, action, target, detail(JSON), created_at, ip)
sync_locks(customer_code PK, locked_by, locked_at, expires_at)  -- 兜底，防死锁
```
索引：`sync_history(customer_code, started_at DESC)`、`audit_log(created_at DESC)`、`user_customer_assignments(user_id)`。

## 鉴权（JWT 单 token + 改密失效）

- 依赖新增：`pyjwt>=2.8.0`、`passlib[bcrypt]>=1.7.4`（追加到 [requirements.txt](file:///f:/项目/客户轨迹自动更新/sync_service/requirements.txt)）。
- `.env` 新增：`ADMIN_USERNAME`、`ADMIN_PASSWORD`、`JWT_SECRET`（缺失则启动失败，禁止默认密钥）、`JWT_EXPIRE_DAYS=7`。
- payload `{sub:user_id, username, role, iat, exp}`，HS256。**不引入 refresh token**——改密/重置后更新 `users.pwd_changed_at`，校验 token 时 `iat < pwd_changed_at` 即拒绝，实现改密即全端踢出。
- 核心函数集中在 [auth.py](file:///f:/项目/客户轨迹自动更新/sync_service/app/services/auth.py)：`hash_password/verify_password`、`create_access_token`、`decode_token`、`get_current_user(Depends)`、`require_admin(Depends)`、`get_customer_if_accessible(code, user)`。

## 权限矩阵

| 资源/动作 | admin | user |
|---|---|---|
| 用户管理（创建/禁用/重置密码） | ✓ | ✗ |
| 客户 CRUD | 任意 | 仅 owned + assigned |
| 分配客户给用户 | ✓ | ✗ |
| 触发同步单客户 | 任意 | 仅 owned + assigned |
| 批量同步所有客户 | ✓ | ✗ |
| 同步历史 | 全部 | 仅自己客户 |
| 审计日志 | ✓ | ✗ |
| 改自己密码 / 创建客户（成 owner） | ✓ | ✓ |
| webhook 测试 | 任意 | owned + assigned |

注入三层 Depends：`get_current_user`（登录）→ `require_admin`（角色）→ `get_customer_if_accessible`（ownership，admin 直通）。

**定时任务**不走 HTTP，`sync_customer(code, triggered_by='system', source='scheduled')` 系统级调用，仍写 sync_history/audit_log，仍受 `customers.enabled` 控制。

## customers.yaml 迁移

`db.init_db()` 在 [main.py](file:///f:/项目/客户轨迹自动更新/sync_service/app/main.py) lifespan 开头调用，顺序：
1. 建所有表（IF NOT EXISTS）
2. `bootstrap_admin()`：users 表空 → 用 `.env` 创建 admin；`ADMIN_PASSWORD` 缺失则启动失败
3. `migrate_customers_from_yaml()`：customers 表空 且 yaml 存在 → 逐条导入，`owner_user_id=admin`，记一条 audit_log
4. `reload_scheduler()` 数据源已切 DB

[config.py](file:///f:/项目/客户轨迹自动更新/sync_service/app/config.py) 改动最小化：`get_customer/list_customers` 改为调 `db.*`（签名不变，调用方无感）；`CUSTOMERS` 全局 dict 与 `reload_customers` 弃用；`DEFAULT_WEBHOOK_URL`、`SMARTSHEET_FIELDS`、`F_*`、`SIGNED_*`、ERP 配置保持不变。yaml 保留为只读种子。

## 并发锁

进程内 `asyncio.Lock` per customer_code 为主，`sync_locks` DB 表兜底（带 `expires_at` 防崩溃死锁，单进程下 asyncio.Lock 已够）。放在 [sync_engine.py](file:///f:/项目/客户轨迹自动更新/sync_service/app/services/sync_engine.py) 或独立 `sync_lock.py`。`sync_customer` 开头 `async with _get_lock(code)`，路由层拿不到锁返回 `409 Conflict`。

## webhook 测试（零脏数据）

企微 webhook 不支持 query/delete，发 add 会产生脏记录。务实方案：**空 body POST 探测 errcode**——企微对空 body 返回 `errcode != 0` 但不写记录，根据 errmsg 区分 `invalid key`（key 无效）vs `参数错误`（key 有效）。放 [qiwai_client.py](file:///f:/项目/客户轨迹自动更新/sync_service/app/services/qiwai_client.py) 的 `webhook_probe(url)` 方法。路由返回 `{reachable, valid_key, errcode, errmsg}`，记一条 audit_log。

## 前端改造（[index.html](file:///f:/项目/客户轨迹自动更新/sync_service/app/static/index.html)）

- 默认登录页 → 存 token 到 localStorage → 切主面板
- 顶部用户信息条：`{username}({role}) [改密] [登出]`
- 全局 fetch 包装：自动加 `Authorization: Bearer`；401 清 token 跳登录
- 按角色渲染菜单：admin 见用户管理/全部客户/分配/审计/同步历史全量/批量同步；user 见我的客户/新增/触发同步/我的历史/改密
- 客户表格行操作按权限显示（admin：分配/删除/启停；user：仅 owned 可删改，assigned 只能同步）

## 验证（端到端）

1. 填 `.env`（ADMIN_USERNAME/ADMIN_PASSWORD/JWT_SECRET），`uvicorn app.main:app --reload`
2. 看日志：建表 → bootstrap admin → 迁移 N 条客户 → 调度器加载 N 任务
3. 浏览器开 `/`，admin 登录，`/auth/me` 返回 role=admin
4. admin 创建 user `alice` → 登出 → alice 登录 → 新增客户 `8888275373`（owner=alice）
5. admin 把迁移来的 `RTBTEST` 分配给 alice
6. alice GET `/customers` 见 2 条；DELETE 别人 owned 客户 → 403；POST `/sync`（全量）→ 403；POST `/sync/8888275373` → 成功
7. 并发两次 `/sync/8888275373`，第二次 409
8. alice `/me/sync-history` 见记录；admin `/sync-history` 见全部；admin `/audit-log` 见登录/创建/分配/同步/改密
9. alice 改密后旧 token 立即 401
10. `/customers/8888275373/webhook-test` 返回 `{reachable:true, valid_key:true}`
11. 临时改 cron 为 `*/2 * * * *`，等触发，sync_history `trigger_source='scheduled'`
12. 回归：同步 8888275373，确认运单去重/record_id 映射/add→update 重试等既有逻辑不受影响（这些路径未改）

## 设计决策摘要

- DB 拆分：record_map.db（同步映射）+ app.db（权限域），职责分离
- JWT 单 token + pwd_changed_at 失效：简单够用，不引入 refresh token
- 权限三层 Depends 声明式注入
- 定时任务无 HTTP 上下文，系统级调用仍写历史/审计
- 并发锁：asyncio.Lock 主 + DB 表兜底
- webhook 测试：空 body POST 探测，零脏数据
- customers.yaml 保留为只读种子
